# OverseasJob.in v0.8.0 — Employer onboarding, human review, owned listing projection (GATED)

**Canonical business requirements:** v1.3.3 `07_RECRUITER_LITE_AND_PARTNER_API.md`, `15_CANONICAL_MODULE_REQUIREMENTS.md`, `16_DATA_AND_OPERATIONS_CONTRACT.md`, and `08_PARTNER_JOB_POSTING_API_OPENAPI.yaml`. This release adds code under existing gates; it does **not** change the source-of-truth business scope, claim a verified employer, or authorise a public launch.

## Implemented code

- `src/EmployerReview.php` and `database/002_employer_review.mysql.sql`: owner-only decision rules; pending→published/rejected/suspended, expected revision and complete reason+actor audit. Publish requires approved org, separate email/domain/representative proof timestamps, named owner approval and evidence reference, valid provider-independent first-party rights, approved apply domain, consent and future expiry. Rejected or suspended unsafe submissions can be decided even if employer status is revoked. **A direct listing becomes publicly eligible only if the audit contains `publish` for that exact current revision.**
- `src/EmployerReview.php` also provides first-party-only, field-whitelisted public projections and a bounded expiry job. An expired, closed, held, unverified, suspended, edited or unreviewed listing never projects. Third-party Jobicy/Himalayas jobs never reach employer/review tables.
- Owner HTTPS/CSRF/password-hash/rate-limited existing `/owner` panel includes a separately gated employer review queue. Private `scripts/employer_review.php` supports `pending`, human `publish`/`reject`/`suspend` with reason, and periodic `expire`; owner identity decision evidence stays in the database. No API bearer may review itself.
- `src/RecruiterPortal.php`, `database/003_recruiter_accounts.mysql.sql`: invitation-only business members; a **code delivered to the recorded email** (8-digit 15-minute single-use HMAC challenge, 5 attempts) plus strong password creates active member state. Login uses hashed IP+email rate counters. Every request re-checks trusted org status/representative/domain/email evidence and member status. Browser session is HTTPS-only, `Secure`, `HttpOnly`, `SameSite=Strict`, short-lived with CSRF and session ID rotation. Dashboard exposes only member's organisation jobs, with a review-gated new/edit/close workflow. No applicant CV/passport database.
- `scripts/recruiter_invites.php` is private CLI and disabled unless a verified mail transport and staging URL are configured. `mail()` submission is **not proof** of inbox delivery; a real recipient must enter the emailed one-time code. No challenge is printed or written into the repository.
- `src/EmployerDomainProof.php`, `src/EmployerDomainMysql.php`, `database/004_employer_domain_proof.mysql.sql`, private `scripts/employer_domain.php`: proof-of-control via `_overseasjob-verify.<domain>` DNS TXT, single use challenge digest and 7-day expiry. DNS confirmation only records domain control; it **never** sets `approved`, `representative_verified_at` or `approved_at`, and a real company/representative/agency/legal check remains separate.
- `/jobs` optionally distinguishes direct reviewed submissions from feed listings; direct details are under `/jobs/direct/job_ID` and are not included under the stricter “India location + timezone confirmed” filter without both pieces of evidence. All direct employer public browsing remains **blocked** unless `EMPLOYER_PUBLIC_ENABLED=1` and the existing overall launch gate passes. There is no `JobPosting` schema and no external syndication.

## Safe staging sequence (operator, not an instruction to auto-approve)

1. Privately inspect Hostinger PHP, HTTPS, MySQL 8, cron, filesystem layout, email transport and backups. Create a dedicated disposable/staging database, restore from an independently verified backup, and run SQL `001`→`002`→`003`→`004` once. Production migration is **blocked** until the real database is independently assessed. Staging scripts must never run on a live unbacked-up employer database.
2. Keep all switches disabled. Run `php tests/mysql_integration_tests.php` **only** with `OJ_MYSQL_INTEGRATION=1`, a disposable DSN whose `dbname=oj_test`, and *test-only* credentials. The GitHub Actions CI matrix includes a disposable MySQL 8 container. Passing disposable MySQL tests proves SQL interactions in CI, **not** Hostinger readiness, e-mail inbox delivery, legal compliance or production security.
3. Create prospective employer orgs only through trusted owner evidence workflow. To prove domain control in staging: private CLI `php scripts/employer_domain.php issue org_ID company.example` creates a DNS TXT instruction. Wait for the operator's genuine DNS update, then `php scripts/employer_domain.php check org_ID company.example` checks **live DNS**. DNS control is not an employment identity certificate.
4. Independently verify company's legal name, representative authorisation, independent contact, appropriate cross-border recruitment and Indian eMigrate/MEA constraints, and a safe owned/approved ATS apply hostname. Only the authorised human owner may record `approved_at`, `approved_by`, `representative_verified_at` and a *real* evidence reference in private DB. **Do not populate this evidence with synthetic/test names in production.**
5. Configure tested outbound mail (`RECRUITER_EMAIL_FROM`, `RECRUITER_VERIFY_URL=https://YOUR-VERIFIED-STAGING-HOST/employers/verify`, private secret). Use CLI `php scripts/recruiter_invites.php org_ID lowercase-recipient@example.org` only after real org approval. Test actual email inbox arrival, one-time challenge, rate limits, session expiry and account revocation before any pilot employer is allowed in.
6. With HTTPS and real DB privileges, stage `/employers/login`, `/employers/verify`, `/employers/dashboard` and `/employers/jobs/new`. First posting must remain pending. Owner logs in via existing `/owner` with CSRF, reviews actual job and proof, records reason and approves/rejects. Verify revision-specific audit and that edits unpublish, close/expiry/suspension hide immediately.
7. **Never** enable `EMPLOYER_PUBLIC_ENABLED` or flip `RELEASE_READY` until global launch gates (real source licences + 14-day inventory, privacy/legal/editorial review, security and accessibility E2E, backup/restore) and employer-specific evidence are complete.
